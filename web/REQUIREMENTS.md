# 前端需求（用户口述的萃取）

> 目的：把对话里散落的前端要求固化下来。**改视觉之前先读这个文件。**
> 结构：① 不可违背的原则 ② 具体规格 ③ 待做 ④ 已否决
> 更新规则：用户每次给新反馈就往对应小节加，**注明日期**。
> 已完成的**不删**，标 ✅ —— 防止后人「优化」掉已经明确要求过的东西。

## ① 不可违背的原则

| # | 原则 | 出处 |
|---|---|---|
| P1 | **几何绝不简化** —— 不做 Douglas-Peucker、不按缩放抽稀、不合并顶点 | 2026-08-02「一定不要做简化」 |
| P2 | **不因为密而隐藏要素** —— 不用 `minzoom` 藏图层。「看不清」用颜色/透明度/叠放顺序解决，不靠删 | 2026-08-02「太密没事，放大能看就行，不要缺东西」 |
| P3 | **实测与推算必须视觉可分** —— 实测＝实心+白描边，推算＝空心圆，面板给黄色警告 | 一贯要求 |
| P4 | **潮流的叠加只改颜色，不改粗细** —— 粗细唯一由电压决定 | 2026-08-02，反复强调过两次 |
| P5 | **不擅自调「发挥」** —— 宽度档位等既定数值不要自己改梯度 | 2026-08-02「不是让你发挥」 |
| P6 | **不画错的几何** —— 宁可线断开，也不画物理上不存在的连接 | 2026-08-02「不能画错的」 |

## ② 具体规格

### 送電線

- 配色**只用青系**，靠彩度区分 5 档。⚠️ **最高压不要往白靠** ——
  `#d6ecff`（明度 .82）会让并走的潮流线看起来「镶了白边」。用彩度不用明度
- 粗细也分 5 档，与颜色同档
- **唯一定义**：`layers.ts` 的 `KV_LINE_WIDTH`。送電線・潮流・流光三者共用

| 电压 | 色 | 宽（z4 / z11） |
|---|---|---|
| ≥500kV | `#29c3ff` | 3.2 / 7.4 |
| 275–499 | `#3fa9e8` | 2.2 / 5.2 |
| 154–274 | `#4f93cc` | 1.5 / 3.6 |
| 66–153 | `#4a7099` | 1.0 / 2.4 |
| <66 / 不明 | `#3f4c5e` | 0.6 / 1.6 |

### 潮流

- **底色和送電線完全一致**（电压青系、同宽）。潮流本身不改变线的颜色和粗细
- 潮流的信息**全部由流光承载**：
  - 流光的**颜色** → 负荷率（见下）
  - 流光的**移动方向** → 潮流正方向
- **几何按区间电压细分**：一条潮流线跨多个电压时（335 条里有 12 条），
  每段用各自的实际电压，宽度才能和底下的蓝线逐段对齐

### 潮流几何的取舍（P6 的具体规则）

用户 2026-08-02 的原话：「实际是很近的地方可能单纯是 500kV 没连到一起，
然后中间的部分 OSM 那边数据是**未分类**而不是就是明确的小线路，那我觉得留着 ok」

| 区间质量 | 判定 | 画不画 |
|---|---|---|
| `real` | 有真实几何，且段电压与线路电压不冲突 | ✅ |
| `short_gap` | 无几何（直线兜底）但 **< 1.5km** —— 近距离的连接缺口 | ✅ |
| `straight` | 无几何且长 —— 会画出**不存在的直连** | ❌ |
| `kv_mismatch` | 段电压 < 线路公称的 50% —— 路径迷进了别的线路 | ❌ |

⚠️ **段电压 = 0（OSM 未分类）不算错误** —— 那是「不明」，不是「已知是低压」。

实测排除 180 区间 / 468 km（含 275kV 线路误走 77kV 线达 22.6km 的情况）。

### 幾何の重なりは**そのまま**にする

異なる線路が同じ区間に重なることがある（実測 156 区間 / 23%）。
経路探索は両端しか知らないため別々の線路が同じ辺に載る一方、
日本は**同塔並架**が多く重なりが物理的に正しい場合もあり、
データからは両者を区別できない。

⛔ **オフセットで描き分けない**（2026-08-02「因为线宽也有定义，所以就重叠得了」）。
線幅は電圧で一意に決まる決まりなので、オフセット量を線幅に追従させると
幅の定義が二重になる。**重なったままでよい**。
クリック時に `shared_count` / `shared_with` で何本共有しているかだけ示す。

### 変電所：不加描边

⛔ **不要给变电所加 `circle-stroke`。**（2026-08-02「变电站去掉 border 试试」）

变电所有 8,994 个、半径只有 1.2–5.5px。原来那圈 0.5px 的暗色描边
（`#0b0f14`，和底图同色）会把每个点边缘啃掉一层，小尺寸下**电压配色基本读不出来**。

密集处糊在一起是预期的，用不透明度（0.85）调，不靠描边分隔、更不靠隐藏（P2）。

### ★ 潮流的方向：不能用绝对值

⛔ **OCCTO 的「潮流方向(正方向)」是参照方向，不是实际流向。**

各线路有一个约定的基准方向，值以它为正——**负值表示实际反向流动**。

实测（2026-07-31）：**464 条线里 189 条（41%）平均潮流为负**。
福冈的例子：

```
脊振西福岡線   正方向「西福岡ss → 脊振ss」   实际 −486MW
             → 真实流向是 脊振 → 西福岡（流入市区）
```

早先用 `abs()` 取平均，符号丢了，流光一律沿几何方向跑，于是
**流入负荷中心的电力被画成流出**（用户 2026-08-02 发现「福冈市区的潮流怎么都是往外走的」）。

**修法**：publish 时若带符号的平均为负，**反转几何坐标序列**（段序和段内点序都反），
并对调 `from`/`to`。流光只是沿线跑 dasharray，几何方向对了方向就对了。

| 字段 | 含义 |
|---|---|
| `mw` | 平均 **\|潮流\|** —— 负荷率着色用（负荷不分方向） |
| `mw_signed` | **带符号**的平均潮流 |
| `flow_reversed` | 几何是否已被反转 |

### 流光

- 光的占比要**大于空白**（2026-08-02「有光的部分占比稍微大一点，现在蓝色有点多」）
- 周期必须**短于最短线段**，否则短线段上会周期性没有光（LESSONS #31）
- 详见 `MapView.tsx` 的 `makeDashSeq` 注释（踩过 5 个坑）

### 负荷率的色标

用户 2026-08-02：「100% 的时候就红色，尽量一天各个时段颜色区分大一点」

⚠️ **色标点要按实际分布放，不能等间距。**
实测（当日平均）：p25 9% / p50 19% / p75 40% / p90 56% / p95 68% / max 92%。
等间距会让 3/4 的区间挤在同一个黄色里。

```
  0%  #fff7b0      40%  #ff8412  ← p75
 10%  #ffe14d ←p25 55%  #ff631c  ← p90
 20%  #ffc81a ←p50 70%  #ff4124  ← p95
 30%  #ffa50f      85%  #ff1f1f
                  100%  #e00000  ← 「100% 就红色」
                  120%  #8f0000
```

⚠️ 现在看到的是**一天压平后的静态快照**。24 小时时序接上后，
同一条线在峰谷间会横跨更大范围，颜色变化会明显得多。色标按 0–120% 定，
时序接上后不用改。

### 圆（発電所）

#### 大小 ＝ 装机容量、**全设备统一一套刻度**

⛔ **不要给不同图层各自的刻度。**（2026-08-02「不要有不一致的，我现在看到 30mw 和
3000mw 的有的几乎大小一样，这个完全不对」）

之前 `plants` 用 10–5,400MW、`sites` 用 1–365MW 两套独立映射，
于是 30MW 在小尺度里接近上限、3000MW 在大尺度里也接近上限，画出来一样大。
现在统一 **1MW–6,000MW**，`capRadius()` / `capIconSize()` / `capStrokeWidth()`
全部从同一个 `capT()` 派生。

#### 刻度是 **0.4 次幂**，不是对数也不是面积正比

| 30MW vs 3000MW | 1MW | 30MW | 3,000MW | 比 |
|---|---:|---:|---:|---:|
| 面积正比 sqrt | 3.0px | 4.3px | 19.2px | 1:4.4，但中间段塌陷 |
| 对数 ln | 3.0px | 12.0px | 24.2px | **1:2.0，差不出来** |
| **0.4 次幂（采用）** | 2.5px | **5.4px** | **26.2px** | **1:4.8** |

两次都调过头过：面积正比是「大的太大」，对数是「小的太大」
（`ln(30)/ln(6000)` 已占 39%）。0.4 次幂在两者之间，中间段 100–1,000MW 不塌陷。

上端 26px → **34px**（2026-08-02「大的可以稍微更大一点」）。

> 两个旋钮分开：**`P`（指数）控制曲线弯曲**，**端点值控制整体大小**。

#### ⚠️ 描边宽度也要随大小变

⛔ **不要用固定值。** 半径 2.5px 的圆配 1.6px 描边 → **描边占了 64%**，
小点看起来全是边框（2026-08-02「小圈的 border 有点大」）。

`capStrokeWidth()` 用同一条 `capT()`，让描边占半径的比例大致恒定：

| 容量 | 半径 | 描边 | 占比 |
|---|---:|---:|---:|
| 1 MW | 2.5px | 0.60px | 24% |
| 100 MW | 7.8px | 1.01px | 13% |
| 6,000 MW | 34.2px | 3.01px | 9% |

#### 内部扇形 ＝ 实时功率百分比

- ⚠️ 扇形是**该时刻的出力 ÷ 容量**（`load`），**不是当日累计的设备利用率**（`cf`）
- 实测差异：原町 实时 94% vs 当日平均 48%；船町 实时 0% vs 当日平均 39%
- 停机座数：实时口径 67 座为 0，平均口径只有 32 座
- 停机时圆环仍在、扇形为空 →「有电站但没发电」和「没有电站」可区分
- 实现：canvas 生成「电源种 × 利用率 21 段」共 147 个图标 + symbol 图层
  （`circle` 画不出扇形）。`icon-allow-overlap: true` 保证密集处不隐藏
- ⚠️ **`icon-size` 的除数是 56 不是 64** —— 图标里画的圆直径是
  `ICON_PX - 8 = 56`，留了 8px 给描边。用 64 换算会让 symbol 比 circle 小 12.5%

#### 侧边栏的容量图例

底边对齐的同心圆（nested circle legend），刻度 **10 / 100 / 1000 MW**。

- ⚠️ **不放 6,000MW** —— 圆太大挤占侧边栏，而该量级的电站极少（2026-08-02）
- ⚠️ 半径**必须调用 `capRadiusPx()`**，不能照抄数值 ——
  地图和图例必须来自同一个函数，否则调刻度时图例会悄悄过时

### 电源种配色：火力三种同色系

（2026-08-02「火力三种用同一色系，黄橙黄红啥的」）

| | 旧 | 新 |
|---|---|---|
| 火力（ガス） | `#4fa3ff` 蓝 | **`#f5c542` 黄** |
| 火力（石油） | `#ff8c42` 橙 | **`#f08a24` 橙** |
| 火力（石炭） | `#8d8d8d` 灰 | **`#d1503a` 赤** |

按碳强度排序，一眼能看出是不是化石燃料。旧配色里三种火力分属三个色系，看不出同类。

顺带挪开两个会撞的：地熱 `#ff6b6b`→`#e0559e`（和石炭的红分不开）、
バイオマス `#b5a642`→`#7fb069`（和ガス的黄分不开）、風力 → `#5ac8fa`（避开新的绿）。

⚠️ **配色定义在两处，必须同步**：`layers.ts` 的 `FUEL_COLOR`（Mapbox 表达式）
和 `pieIcons.ts` 的 `FUEL_COLORS`（canvas 要真实色值，不能用表达式）。
两边都写了注释互指。

### ⚠️ 圆的大小基于容量，但容量的口径不统一

容量 183/183 座（100%）都有值，**但来源分五级，精度差很多**。
`capacity_source` 字段标了每座是哪一级，解读圆的大小时要看它：

| `capacity_source` | 座数 | 口径 | 可信度 |
|---|---:|---|---|
| `GEM_operating` | 122 | 现役（`Status=operating` 的 unit 合算） | 高 |
| `GEM_by_location` | 20 | 用已匹配的坐标反查 GEM（绕开名字） | 高 |
| `AJG_installed_ever` | 18 | 厂级、带出处，**但含废炉机组** | 中 |
| `AJG_unit_estimate` | 15 | AJG 行级估算合算 | **低** |
| `xref`（人工） | 6 | 逐条查证，note 写了依据 | 中 |
| `observed_minimum` | 2 | ⚠️ **用当日实测最大出力兜底，是下限不是额定** | **最低** |

⚠️ 后两级的圆，大小只反映「至少这么大」，不是真实装机。

### 前端可用字段（plants.geojson）

| 字段 | 含义 | 用途 |
|---|---|---|
| `capacity_mw` | 装机容量 | **圆的大小**（对数） |
| `load` | 该时刻出力 ÷ 容量 | **扇形角度** |
| `mw_now` | 该时刻出力（MW） | 信息面板 |
| `slots_mw` | **48 个 30 分时点的出力** | 时间轴（R1）直接用这个，不用再取数 |
| `cf` | 当日平均利用率 | 仅供参考，**不要用于扇形** |
| `fuel` | 电源种 | 颜色 |
| `capacity_source` | 容量来源 | 判断可信度 |
