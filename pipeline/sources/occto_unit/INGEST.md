# OCCTO ユニット別発電実績公開システム — 逐机组発電実績

> **状态：已实装并跑通。** 发现于 2026-08-01，同日完成。
> 它推翻了立项调研里「逐机组出力不公开」的结论。

## ★ 为什么这条重要

立项时的调研笔记写着两条，**都是错的**：

| 原结论 | 实际 |
|---|---|
| 「逐机组出力…确认不公开，不要再找」 | **公开**，30 分颗粒度 |
| 「机组级 + 逐时出力 + 坐标 三合一的官方源不存在」 | 机组级 + 30 分出力**有官方源**；配上 AJG / GEM 的坐标就凑齐三合一 |

也就是说，`发电所コード → 坐标` 的映射一旦建起来，就能做**逐机组出力的地图动画** —— 这是公开世界没有的东西。

## 概要

| 项 | 值 |
|---|---|
| 系统 | https://hatsuden-kokai.occto.or.jp/hks-web-public/ |
| 数据来源 | **一般送配電事業者的计测值** |
| 覆盖 | 10 区域 |

| 更新 | 每日 **15:30 前后**自动更新；系统异常时顺延到次营业日 |
| 单位 | kWh |
| 值的性质 | **速报値** —— 系统自己声明可能有数据缺失 |

## 官方手册怎么说（`20240326_yhks.pdf`）—— 与实测的差异见下

手册的「CSV 出力項目一覧」（表 3-2）：

```
1 発電所コード
2 エリア名
3 発電所名
4 ユニット名
5 発電方式名
6 対象日            YYYY/MM/DD
7 発電実績_0030     ZZZZZZZZ9
8 発電実績_0100
9 発電実績_0130
10 発電実績_0200
…                  以 30 分递增，至 48 个断面
```

⚠️ **手册与实际有出入，以实测为准**：

| 项 | 手册说 | 实测 |
|---|---|---|
| 対象日 | 单日 | **是区间**（`tgtDateDateFrom` / `tgtDateDateTo`） |
| エリア / 発電方式 | 必须 | **可选 `99`=すべて**，一次拿全 |
| 取数方式 | CSV 保存按钮 | **`search` 端点直接返回 JSON**，比 CSV 更好用 |

手册是 2023-09 版，界面后来改过。**凡是从手册推出来的请求量估算都要重算。**
（我据手册估过「天数 × 区域 × 発電方式 = 最多 77,000 次请求」，实际是 **859 次**。）

⚠️ 注意：首页（ホーム画面）显示的是**按発電方式聚合的日次面积图**，不是机组级。
机组级在「ユニット別発電実績」タブ →「ユニット別発電実績公開」。第一次调查时
只看到首页就差点得出「只有聚合值」的错误结论。

## 获取

**类型：`auto`** —— 无需账号，但首次访问要过「免責事項同意」画面。

```bash
python -m pipeline.sources.occto_unit.ingest              # 最近 7 天（默认）
python -m pipeline.sources.occto_unit.ingest --days 30
python -m pipeline.sources.occto_unit.ingest --days 2 --include-today --force  # 30 分钟增量
python -m pipeline.sources.occto_unit.ingest --date 20260730
python -m pipeline.sources.occto_unit.ingest --from 20240325 --to 20241231
python -m pipeline.sources.occto_unit.ingest --all        # 2024-03-25 至今
```

### 调用流程（三步）

```
1. GET  /hks-web-public/info/home              未同意时 302 → 同意页，同时拿到 session cookie
2. POST /hks-web-public/disclaimer-agree/next  agreed=0
3. POST /hks-web-public/info/hks/search        → JSON
```

### 检索参数（一次拿全区域 × 全电源种 × 单日）

```
htdnsCd  = ''      発電所コード（留空 = 不限）
htdnsNm  = ''      発電所名
unitNm   = ''      ユニット名
areaCheckbox          = 99     99 = すべて（也可 01–10 逐个）
hatudenHosikiCheckbox = 99     99 = すべて（也可 01–09 逐个）
tgtDateDateFrom = YYYY/MM/DD
tgtDateDateTo   = YYYY/MM/DD
```

**一天一次请求就够** —— 全量 859 天约 **29 分钟 / 525MB**。

## 已知坑

- **与 HJKS 会有乖离**。系统明说：因为是一般送配電事業者的计测值，试运转和计测时机
  会让它与 JEPX 的 HJKS 公开信息对不上。两者不要混用，也不要互相「校正」。
- **2024-03-24 以前是试验数据**，不能当实绩用。
- **`agreed=0` 才是同意，`1` 是不同意**。页面 JS（`HKSHS004.js`）的 toggle：
  载入时隐藏字段被置 `'1'`（未勾选），勾选后才变 `'0'`。按直觉传 `1` 或 `true` 都会被打回同意页。
- **检索表单上有 `data-recordcountproperty="1000"`**。单日约 471 条安全，
  但**按区间查会成倍增长**，可能被这个上限静默截断。所以固定一天一次，不做区间查询。
  ingest 里对条数 ≥1000 会告警。
- `info/hks/downloadCsv` 端点存在但 POST 返回 **405**。不用管它，走 `search` 的 JSON。
- **本系统推荐环境是 Edge**。若自动化遇到怪行为，UA/浏览器兼容是一个排查方向。
  （实测用我们自己的 UA 无碍。）

## 与既有源的关系

| 源 | 颗粒度 | 与本源的关系 |
|---|---|---|
| エリア需給実績 | 区域 × 电源种 × 逐时 | 更粗，但历史到 2016，且是**逐时**已足够 v0 |
| 本源 | **机组 × 30 分** | 唯一的机组级出力，历史只到 2024-03-25 |
| GEM | 机组级**属性**（燃料/容量/坐标） | 提供属性与坐标，与本源用発電所名/コード 做 join |
| AJG | 发电所几何 | 提供坐标的另一条路 |

**v0 不依赖本源**（区域级已够）。它的价值在 v0 之后：机组级出力 + 坐标 = 公开世界没有的可视化。
